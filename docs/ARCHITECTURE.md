# Архитектура

Один репозиторий и один собираемый Docker-образ для API и worker. Frontend раздаётся API из `dist/client`. Очередь лежит в PostgreSQL, поэтому Redis не расходует память VPS. Видео хранится в Docker volume; в Git и PostgreSQL бинарные файлы не попадают.

```mermaid

  B[Браузер ученика или администратора] -->|HTTPS| C[Caddy]
  C --> A[Fastify API + React]
  A --> DB[(PostgreSQL)]

  W[FFmpeg worker · 1 задача] --> DB
  W --> V
  V -->|Приватный HLS через API| A
```

## Основные сущности

```mermaid
erDiagram
  USERS ||--o{ SESSIONS : authenticates
  USERS ||--o{ ENROLLMENTS : enrolled
  COURSES ||--o{ ENROLLMENTS : assigns
  COURSES ||--o{ LESSONS : contains
  LESSONS }o--o| MEDIA : video_or_scene
  USERS ||--o{ PROGRESS : learns
  LESSONS ||--o{ PROGRESS : tracks
  USERS ||--o{ ATTEMPTS : submits
  LESSONS ||--o{ ATTEMPTS : evaluates
  USERS ||--o{ CERTIFICATES : earns
  COURSES ||--o{ CERTIFICATES : completes
  USERS ||--o{ UPLOADS : uploads
```

- Роли: администратор управляет материалами и пользователями; ученик видит опубликованные открытые и назначенные курсы.
- Самостоятельная регистрация создаёт только ученика. Отключается `REGISTRATION_OPEN=false`. Почта в этой версии не подтверждается через SMTP.
- Открытый курс виден в каталоге; доступ к материалам появляется после записи. Закрытый курс назначает администратор.
- Для теста хранятся вопросы, ответы и проходной процент. Для визуального упражнения — изображение, инструкция, от 1 до 20 прямоугольников с оценкой `score=100` (зелёный) или `score=50` (жёлтый), начальная позиция персонажа и пояснение. Координаты нормализованы в проценты; при пересечении зон берётся максимальная оценка, вне зон — 0%. Прежний формат с одним `target` поддерживается и преобразуется в `targets` при сохранении; прежние зоны без `score` дают 100%. При отсутствии стартовой позиции используется X=50%, Y=85%. Ответы, пояснения и зоны исключаются из API ученика; стартовая позиция передаётся для отображения. Поля `video_id` и `image_id` используются и для вложений обычного теста: сначала показывается видео, затем фото, затем вопросы. У визуального задания изображение остаётся рабочей сценой.
- Вопрос теста поддерживает `multiple=true` и массив `correctIndexes` для нескольких правильных вариантов. Прежний `correctIndex` и отсутствие `multiple` означают выбор одного ответа. Ученику передаётся только тип выбора, без обоих полей правильных ответов. Множественный ответ передаётся массивом уникальных индексов; порядок не важен. Процент вопроса: `max(0, (верные выбранные − неверные выбранные) / количество правильных × 100)`. Вопрос с одним ответом даёт 100 или 0. Оценка урока — среднее вопросов, до сотых процента. Оценка курса — среднее тестовых и визуальных уроков; видео исключены.
- Прогресс уникален по паре ученик–урок. Отправка проверяется сервером в транзакции с блокировкой строки прогресса; `submitted_at` запрещает вторую отправку даже из двух вкладок одновременно (HTTP 409). Незаполненная или некорректная форма не расходует отправку. `attempt_id` связывает итог с неизменяемой попыткой, `attempts.details` сохраняет формулировки и проценты вопросов на момент ответа. Любой корректно отправленный ответ завершает урок, независимо от оценки. XP начисляются один раз за завершение: видео 30, тест 50, визуальная практика 75. Уровень — каждые 200 XP.
- Ответ API на отправку содержит только подтверждение и признак доступности результатов. До завершения всех текущих уроков API ученика скрывает `score` и `passed`, а страница результатов возвращает HTTP 409. Пинги видеоплеера также не раскрывают оценки. После курса доступны общий и поурочные проценты, без ключей ответов и оценок отдельных вопросов. Администратор видит текущие результаты и снимки оценок вопросов в отчёте; доступны сводный и поурочный CSV.
- Сертификат выпускается сервером после завершения всех уроков и достижения порога в каждом задании (визуальное — 100%); уникален по паре ученик–курс. Завершённый с низкими оценками курс сохраняет результаты, но не выдаёт сертификат.
- Опубликованные и начатые курсы редактируются на месте; существующие результаты и сертификаты сохраняются. Добавленные уроки не считаются пройденными автоматически. Прежний сертификат остаётся подтверждением исторического прохождения; новый сигнал завершения курса появляется только после всех текущих уроков. «Новая версия» остаётся доступной для независимой программы. Изменения программы и публикация сериализуются блокировкой строки курса. В опубликованном курсе допускаются только готовые медиа. При удалении отдельного урока удаляются его результаты и баллы, сертификаты курса сохраняются; удаление последнего урока автоматически снимает курс с публикации.
- Администратор может удалить любой курс после явного подтверждения, включая начатые и завершённые. Каскадные внешние ключи атомарно удаляют его уроки, назначения, прогресс, попытки и сертификаты. Баллы курса исчезают вместе с прогрессом. Общие медиафайлы и другие курсы сохраняются.

## Видео

1. Администратор создаёт upload session, сервер проверяет лимит и запас диска.
2. Браузер читает `File.slice()` и отправляет части с `Upload-Offset`. В памяти находится только одна часть.
3. Смещение фиксируется в транзакции под блокировкой строки. Файл синхронизируется до записи смещения. При восстановлении лишний хвост после незавершённой транзакции обрезается.
4. Браузер хранит ID сеанса и отпечаток размера, имени, времени изменения, первых и последних 64 КиБ. После обрыва выберите исходный файл в том же браузере. Это механизм поиска сеанса, не криптографическое доказательство неизменности всего файла.
5. После получения всех байтов media-задача попадает в PostgreSQL. Worker берёт одну задачу с `FOR UPDATE SKIP LOCKED`, обновляет lease каждые 20 секунд. Задачу после аварии можно подобрать через 2 минуты; после трёх аварий или ошибки обработки доступен ручной повтор.
6. Worker проверяет сигнатуру контейнера, использует принудительный MP4/MOV либо Matroska/WebM demuxer и файловый протокол без доступа к сети. Создаёт H.264/AAC HLS и постер. Варианты не повышают исходное вертикальное разрешение. Размеры кадра ограничены 8K, длительность — 7 суток; тайм-аут одной команды кодирования — 6 часов. Для более длинных задач потребуется расширение worker.
7. До статуса `ready` материалы недоступны. После него исходник удаляется; HLS и постер раздаются API с проверкой доступа для каждого запроса.
8. Видеоплеер отправляет интервалы просмотра; сервер ограничивает прирост прошедшим временем и скоростью. Простая перемотка к концу не завершает видеоурок. Видеовступление в тесте сохраняет позицию и время, но не завершает задание и не меняет заработанные за него баллы. При замене видео состояние просмотра сбрасывается отдельно от результата задания. При скорости 2× учитывается просмотр в ускоренном темпе. Не является прокторингом.

В текущей версии нет S3, CDN или аппаратного кодирования. Обработка больших роликов на 1 CPU может занять значительное время. Лимит исходника не гарантирует достаточность места для любого содержимого: следите за диском и очередью.

## Защита и эксплуатация

- Scrypt с отдельной солью, случайные непрозрачные сессии. В БД хранится хеш сессионного токена. Cookie: HttpOnly, SameSite=Lax, Secure в production.
- CSRF-токен для мутаций авторизованного пользователя и проверка Origin. API и frontend используют один origin.
- Общий лимит запросов авторизованных пользователей считается по аккаунту, чтобы ученики за одним IP не блокировали друг друга. Логин и регистрация ограничены отдельно по IP. Серверные роли, валидация Zod, параметризованный SQL.
- База и API не публикуют порты в боевом Compose; наружу доступны только Caddy 80/443. Поэтому production API доверяет proxy headers от внутренней сети.
- Изображения ограничены 10 МиБ и 32 мегапикселями, перекодируются в WebP. SVG от пользователей не принимается.
- Пути медиа формируются из UUID; имена исходников не используются в файловых путях. Ответы не содержат паролей или токенов БД. CSV защищает текстовые ячейки от формул.
- Требуются регулярные обновления образов, резервные копии БД **и** media, внешний мониторинг, учёт требований к персональным данным вашей организации. Данные не отправляются внешним сервисам аналитики.
- PostgreSQL — источник постоянного состояния. Миграции при запуске API и worker выполняются транзакционно под advisory lock; версии записываются в `schema_migrations`. `knowledge-assessment-v1` добавляет данные отправки и дробные оценки. Прежние итоговые оценки и сертификаты сохраняются; при наличии только неудачных попыток фиксируется первая. Прежние попытки не удаляются. Автоматического down-migrate нет; восстановление резервной копии заменяет всю схему одной транзакцией, затем приложение применяет миграции.

Контейнеры ограничены 384 МиБ для API, 768 МиБ для worker, 256 МиБ для PostgreSQL и 96 МиБ для Caddy. Остальная память остаётся ОС. Значения — стартовая конфигурация, не результат нагрузочных испытаний на SpaceWeb.
