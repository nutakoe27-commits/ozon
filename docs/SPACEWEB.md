# Развёртывание на SpaceWeb VPS

Целевой сервер: **Ubuntu 26.04 LTS, 2 CPU, 2 ГБ RAM, 50 ГБ NVMe**. Домен платформы: **learn.krichiginmo.ru**. Приложение работает в Linux-контейнерах, отдельная установка Node.js, PHP или MySQL на VPS не нужна.

Команды ниже выполняются через SSH от root либо через `sudo`. Не присылайте пароли, приватные ключи или содержимое `.env` в чат и не добавляйте их в Git.

## 1. DNS и доступ к портам

В панели DNS домена `krichiginmo.ru` создайте запись:

| Тип | Имя     | Значение                           |
| --- | ------- | ---------------------------------- |
| A   | `learn` | публичный IPv4 вашего VPS SpaceWeb |

Если есть AAAA для `learn`, она должна указывать на работающий IPv6 этого VPS; иначе удалите ошибочную AAAA. Дождитесь обновления DNS. Порты TCP 80 и 443 должны быть доступны из Интернета для выдачи HTTPS-сертификата. UDP 443 используется для HTTP/3, но для работы сайта не обязателен.

Проверьте, что порты 80/443 не заняты другим веб-сервером или панелью:

```bash
ss -ltnp | grep -E ':80 |:443 ' || true
```

Боевой Compose самостоятельно запускает Caddy. При существующем Nginx/панели не запускайте второй reverse proxy на тех же портах: сначала выберите, какой из них обслуживает домен. Настоящую публичную выдачу сертификата можно проверить только после корректного DNS.

## 2. Установка инструментов

```bash
apt-get update
apt-get install -y docker.io docker-compose-v2 git openssl ca-certificates curl dnsutils
systemctl enable --now docker
docker version
docker compose version
```

Нужен Docker Compose **v2**, не старый Python `docker-compose`. Если пакетный набор вашего образа Ubuntu отличается, установите Docker Engine и Compose по [официальной инструкции Docker](https://docs.docker.com/engine/install/ubuntu/), сохраняя проверку подписей репозитория.

Если вы используете UFW, сначала сохраните доступ к SSH:

```bash
ufw allow OpenSSH
ufw allow 80/tcp
ufw allow 443/tcp
```

Само включение firewall согласуйте с текущей конфигурацией доступа. База и API в Compose не публикуют порты; не добавляйте наружу 5432 или 3000.

## 3. Получение проекта и настройка

```bash
git clone https://github.com/nutakoe27-commits/ozon.git /opt/praktika
cd /opt/praktika
bash scripts/configure.sh learn.krichiginmo.ru admin@example.ru
```

**Замените `admin@example.ru` на вашу действующую почту.** Это логин администратора и контакт Let's Encrypt. Третьим аргументом скрипта можно указать отдельную почту для HTTPS. Для приватного репозитория используйте настроенный GitHub-доступ сервера.

Скрипт создаёт `.env` с уникальными случайными паролями БД и администратора и правами 600. Существующий `.env` никогда не перезаписывается. Откройте его только в своём SSH-сеансе:

```bash
nano .env
```

Проверьте `DOMAIN`, `ADMIN_EMAIL`, `ACME_EMAIL`. Сохраните начальный `ADMIN_PASSWORD` в менеджере паролей. Пароль PostgreSQL генерируется шестнадцатеричным, чтобы его можно было безопасно использовать в connection string. При ручной настройке используйте `.env.production.example`.

Начальные параметры под ваш VPS:

```dotenv
DOMAIN=learn.krichiginmo.ru
UPLOAD_MAX_BYTES=10737418240
TRANSCODE_THREADS=1
MAX_VIDEO_HEIGHT=720
REGISTRATION_OPEN=true
DISK_RESERVE_BYTES=2147483648
```

`REGISTRATION_OPEN=true` включает самостоятельную регистрацию. Можно переключить в `false`; администратор по-прежнему сможет создавать аккаунты. Изменения применяются при `docker compose up -d`.

## 4. Сборка и запуск

Собирайте один образ последовательно, чтобы не расходовать память на параллельные сборки:

```bash
docker compose build app
docker compose up -d --no-build
docker compose ps
docker compose logs --tail=100 app worker caddy
curl --fail https://learn.krichiginmo.ru/api/health
```

Ответ проверки — `{"status":"ok"}`. В Caddy должен появиться успешно выданный сертификат. Первый запуск создаёт схему и администратора, но **не демонстрационные аккаунты**. Войдите на `https://learn.krichiginmo.ru`, используя значения из `.env`, затем измените пароль в настройках аккаунта.

Проверьте один настоящий курс: загрузите небольшой MP4, дождитесь «Готово», создайте тест и визуальное задание, опубликуйте курс, зарегистрируйте ученика и пройдите уроки. Это проверит вашу сеть, диск, DNS и браузер вместе. Затем переходите к большим файлам.

Существующий аккаунт не меняет пароль при редактировании `ADMIN_PASSWORD` в `.env`: используйте настройки аккаунта или административный сброс. Восстановить доступ при утрате всех администраторов можно через отдельную доверенную административную процедуру в БД; публичного обхода входа нет.

## 5. Хранение и ресурсы

Постоянные Docker volumes: `praktika_db` — данные PostgreSQL, `praktika_media` — видео/сцены, `praktika_caddy_data` — HTTPS-сертификаты. Перезапуск и пересборка приложения их сохраняют. **Не выполняйте `docker compose down -v` на рабочей среде**: `-v` удаляет данные.

```bash
docker stats --no-stream
docker system df
df -h
```

На диске 50 ГБ нельзя хранить видео без ограничений. Учитывайте ОС, образы, БД, исходник в процессе обработки, все варианты HLS и резервные копии. Лимит 10 ГиБ на файл можно поднять только после расширения диска. Проверка свободного места резервирует запас, но не предсказывает итоговый битрейт любого видео.

Исходник после успешной обработки удаляется. Неудачные материалы остаются для повтора; удалите ненужный неиспользуемый материал через медиатеку. Учебный оригинал для архива храните отдельно. При росте видеотеки расширьте диск или запланируйте интеграцию S3/CDN.

Лимиты памяти и CPU заданы в Compose. Обработка идёт по одному видео, один поток FFmpeg, варианты до 720p. Скорость обработки и число одновременно смотрящих учеников зависят от исходников, сети и диска. Нагрузочная ёмкость этого тарифа заранее не заявляется; протестируйте свой типичный сценарий перед массовым запуском.

## 6. Резервные копии

```bash
cd /opt/praktika
bash scripts/backup.sh /var/backups/praktika
```

Скрипт временно останавливает API и worker для согласованной копии, сохраняет дамп PostgreSQL, архив media и SHA-256, затем запускает сервисы снова. Caddy в это время может возвращать ошибку недоступности. Выполняйте в период минимальной активности. Храните копии также **вне VPS**; `.env` сохраните отдельно в защищённом хранилище. Архивы могут содержать персональные данные и материалы обучения.

Пример ежедневного задания root-cron (03:00 по часовому поясу сервера):

```cron
0 3 * * * /bin/bash /opt/praktika/scripts/backup.sh /var/backups/praktika >> /var/log/praktika-backup.log 2>&1
```

Настройте ротацию и вывоз копий: автоматическое удаление архивов специально не включено. Проверьте восстановление на отдельной машине до эксплуатации.

Восстановление **заменяет текущие БД и media**. Сначала проверьте нужную копию и остановите работу пользователей:

```bash
CONFIRM_RESTORE=yes bash scripts/restore.sh /var/backups/praktika/praktika-YYYYMMDDTHHMMSSZ
```

Аргумент — общий префикс без `.dump`. Скрипт проверяет контрольные суммы и оставляет сервисы остановленными, если восстановление не удалось. На новом сервере заранее установите проект, создайте `.env` и выполните `docker compose up -d db`. Пароль БД должен соответствовать новой базе. При восстановлении из копии исходный администратор восстанавливается из БД.

## 7. Обновление

```bash
cd /opt/praktika
bash scripts/backup.sh /var/backups/praktika
git pull --ff-only
docker compose build --pull app
docker compose up -d --no-build
curl --fail https://learn.krichiginmo.ru/api/health
```

Обновление PostgreSQL внутри ветки 17 возможно после резервного копирования (`docker compose pull db`). Переход на следующую major-версию БД требует отдельной миграции. Не заменяйте тег PostgreSQL произвольно.

## Если что-то не запускается

| Симптом                             | Проверка                                                                                             |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Caddy не получает сертификат        | A/AAAA домена, доступность 80/443, отсутствие другого процесса на порту, `docker compose logs caddy` |
| API не готов                        | `docker compose logs app db`, корректность `.env`, пароль БД, свободный диск                         |
| Видео остаётся в очереди            | `docker compose ps worker`, `docker compose logs worker`                                             |
| Обработка видео завершилась ошибкой | Подробности в медиатеке, свободный диск, контейнер исходника, `docker stats`; затем ручной повтор    |
| CSRF / источник запроса не разрешён | `DOMAIN` должен совпадать с фактическим доменом браузера; после изменения перезапустите контейнеры   |
| Ошибка 507 при загрузке             | Нужен запас на исходник и обработку; освободите или расширьте диск                                   |
| Возобновление не найдено            | Выберите тот же файл в том же браузере; очистка браузерного хранилища удаляет локальный ID сеанса    |

Контейнерный запуск и функциональность проверяются в среде разработки. Установку именно на вашем SpaceWeb VPS, настройки DNS и публичный HTTPS необходимо подтвердить на сервере после выполнения этих шагов.
